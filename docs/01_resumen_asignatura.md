# 01 Resumen asignatura

## Contexto

La Evaluacion Parcial 3 pide consolidar un proyecto de microservicios construido durante el semestre. El foco ya no es solo tener CRUD: se debe demostrar arquitectura distribuida, documentacion viva, pruebas unitarias, API Gateway, YAML y despliegue.

## Material base revisado

- `Evaluacion Parcial 3_Estudiante.pdf`: rubrica oficial, porcentajes y exigencias de entrega/defensa.
- `3.1.1 Documentacion de Microservicios.pdf`: OpenAPI/OAS como estandar de documentacion.
- `3.1.2 Guia practica - Proyecto Biblioteca Duoc - Swagger.pdf`: implementacion de Swagger con Springdoc y anotaciones.
- `3.1.3 Implementacion de HATEOAS en la Documentacion de APIs.pdf`: concepto y uso de links hipermedia.
- `3.1.4 Guia practica y ejercicios - Proyecto Biblioteca Duoc - HATEOAS.pdf`: dependencia HATEOAS, assemblers y endpoints `/api/v2`.
- `3.1.5 Pruebas unitarias en proyectos de microservicios.pdf`: JUnit 5, Mockito, Given-When-Then y aislamiento.
- `3.2.1 API Gateway.pdf`: Gateway, YAML, rutas, predicados, filtros y Eureka como posible mejora.
- `3.2.2 Despligue de microservicios.pdf`: Docker, PaaS, variables de entorno, puertos y perfiles.

## Resultado esperado por la asignatura

El proyecto debe quedar defendible como ecosistema de microservicios:

- Al menos 10 microservicios por equipo.
- Separacion CSR en cada microservicio.
- Reglas de negocio y validaciones defendibles.
- Comunicacion REST entre servicios.
- Pruebas unitarias con JUnit y Mockito.
- Cobertura objetivo de 80%.
- Swagger/OpenAPI en endpoints principales.
- API Gateway con rutas, predicados y filtros.
- YAML para configuracion relevante.
- Docker Compose funcional y, si corresponde, plan de despliegue remoto.
- README y guia de defensa claros.
